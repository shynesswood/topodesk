# 凭证存储风险评估

## 范围

评估 TopoDesk 当前对 SSH 密码/私钥和 RDP 密码的存储方式和安全风险。

评估日期：2026-05-25

## 当前状态

### 存储路径

```
NodePanel (UI 输入)
  → topologyStore.updateNode() (Zustand 内存)
  → projectService.SaveProject() → projectToWails()
  → Wails IPC → app.go → project.Save()
  → json.MarshalIndent() → os.WriteFile(path, data, 0600)
  → .topology.json (明文文件)
```

### 凭证字段

| 字段 | 位置 | 风险等级 |
| --- | --- | --- |
| `Node.SSH.Password` | 项目 JSON 明文 | 高 |
| `Node.SSH.PrivateKey` | 项目 JSON 明文 | 严重 |
| `Node.RDP.Password` | 项目 JSON 明文 | 高 |

### 传输路径

- Wails IPC 传输：进程内通信，不经过网络，传输安全风险低。
- 文件权限：0600（仅用户可读写），无加密。
- 内存：Zustand 内存中可被 DevTools 读取。

## 风险评级

| 维度 | 评级 | 说明 |
| --- | --- | --- |
| 机密性 | **严重** | 凭证以明文存储在 JSON 文件中 |
| 完整性 | 低 | 文件被篡改可导致凭证错误，易检测 |
| 可用性 | 中 | 无凭证则远程命令不可用 |
| 整体 | **高** | 文件泄露 = 凭证泄露，运维工具涉及多台服务器 |

## 攻击场景

1. **文件共享泄露**：用户将 `.topology.json` 通过邮件 / IM / 网盘分享，凭证随之泄露。
2. **版本控制泄露**：用户将 `.topology.json` 提交到 Git，凭证进入仓库历史。
3. **备份泄露**：备份软件复制文件，凭证扩散到多个位置。
4. **恶意软件读取**：运行中的机器被植入恶意软件，读取用户目录下的拓扑文件。
5. **DevTools 读取**：`wails dev` 模式下的浏览器 DevTools 可读取 Zustand 状态中的明文凭证。
6. **SSH 中间人攻击**：当前使用 `ssh.InsecureIgnoreHostKey()` 跳过主机密钥校验。这是有意的简化：运维工具面向受控网络环境，由运维人员负责确认目标 IP 可信。

## 缓解方向与性价比

### 快速缓解（低工作量，推荐立即实施）

| 方案 | 工作量 | 效果 |
| --- | --- | --- |
| **项目 JSON 文件权限改为 0600** | 1 行代码 | 阻止同机其他用户读取 |
| **添加 .gitignore 规则屏蔽 .topology.json** | 1 行代码 | 防止误提交到 Git |
| **UI 中密码字段始终使用 `type="password"` 的 Input.Password** | 已实施 | 屏幕防窥 |
| **新建项目欢迎页提示用户凭证以明文保存** | 1 天 | 用户知情 |

### 中期缓解（中等工作量）

| 方案 | 工作量 | 效果 |
| --- | --- | --- |
| **AES-256-GCM 加密项目文件** | 3-5 天 | 文件内容不可直接读取 |
| **应用层加密密钥从用户主密码派生** | 3-5 天 | 需要用户输入密码才能解密项目 |

### 长期方案（高工作量）

| 方案 | 工作量 | 效果 |
| --- | --- | --- |
| **系统钥匙串集成**（Windows Credential Manager / macOS Keychain / Linux Secret Service） | 1-2 周/平台 | 凭证由 OS 管理，应用不存储明文 |
| **加密项目文件 + 密钥存储在钥匙串** | 2-3 周 | 最高安全级别 |

## 建议实施路线

### 阶段 1（本次迭代，0.5 天）

1. `internal/project/project_service.go` 中 `os.WriteFile(path, data, 0644)` 改为 `0600`。
2. 根目录 `.gitignore` 添加 `*.topology.json`。
3. 首次创建项目时弹窗提示："节点密码和私钥将以明文保存在项目文件中，请注意文件安全"。

### 阶段 2（下个迭代，5 天）

4. 引入 AES-GCM 加密整个项目文件。
5. 用户首次使用时设置项目加密密码（主密码）。
6. 保存时加密，加载时用主密码解密。
7. 用户在本次会话期间只需输入一次主密码。

### 阶段 3（长期规划）

8. 集成系统钥匙串管理主密码。
9. per-node 独立凭证支持（仅该节点加密）。
10. 考虑对外部密钥管理系统的支持。

## 当前缓解措施（已落地）

- UI 密码输入使用 `Input.Password` 控件（屏幕防窥）✅
- 本评估文档和 ADR-005 记录了风险 ✅
- 项目文件权限 0600 ✅
- `.gitignore` 屏蔽 `*.topology.json` ✅
