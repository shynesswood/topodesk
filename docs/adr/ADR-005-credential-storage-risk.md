# ADR-005: 凭证存储风险

## 状态

已接受（临时状态）

## 背景

当前 SSH 密码、私钥和 RDP 密码直接存储在节点字段中，随项目 JSON 文件保存。JSON 文件为明文，任何人读取文件即可获取凭证。

## 决策

当前版本不对凭证做加密或分离存储。将此风险明确记录，并在编码规则和安全规则中约束不得扩大该风险。

## 理由

- 首版快速交付功能。
- 凭证加密或钥匙串集成需要额外设计和平台适配。
- 用户文件存储在自己设备上，风险可控但需明确告知。

## 安全约束

- 新增功能不得将凭证写入其他文件、日志或网络传输。
- 不得在 UI 或日志中明文展示密码。
- 不得将密码字段暴露给剪贴板、分享或导出功能。
- 新增远程能力时必须保持凭证只在节点字段中存储。

## 未来方向

- 评估系统钥匙串集成。
- 引入 AES 加密保存项目文件中的凭证字段。
- 支持外部密钥管理或环境变量注入。
- 在 UI 中增加凭证管理模式和密码确认提示。

## 替代方案

| 方案 | 当前阶段否决原因 |
| --- | --- |
| 强制加密存储 | 增加实现复杂度，首版暂缓 |
| 禁止保存凭证 | 影响远程命令执行功能易用性 |
| 每次使用时输入密码 | 运维场景下频繁输入体验差 |
