# ADR-002: 拓扑 JSON 格式与版本化

## 状态

已接受

## 决策

使用单一 `.topology.json` 文件作为项目持久化格式，顶层包含 `version` 字段，当前版本号为 `1`。

## 理由

- 单文件便于用户管理和分享拓扑项目。
- `version` 字段预留未来格式迁移入口。
- JSON 格式易于人工检查和调试。

## 影响

- 所有项目数据（包括当前不加密的凭证）都保存在同一个 JSON 文件中。
- Go 模型和 TypeScript 类型必须保持同步，任何新增字段都需要同时更新两个语言的模型和序列化/反序列化逻辑。
- `frontend/src/services/projectService.ts` 的双向转换是高耦合高风险点。

## 当前风险

- `projectToWails` 和 `projectFromWails` 容易遗漏字段，当前已经存在已知不同步项：
  - 节点 `os`、`rdp`、`commands` 可能在保存加载链路中丢失。
  - 连线 `sourceHandle`、`targetHandle`、`type` 可能在保存加载链路中丢失。
- 未来版本升级需要制定明确的迁移策略。

## 替代方案

| 方案 | 否决原因 |
| --- | --- |
| SQLite | 增加依赖复杂度，不便于用户分享 |
| 多文件拆分 | 增加管理和同步复杂度 |
| 二进制格式 | 不便于人工检查和调试 |
